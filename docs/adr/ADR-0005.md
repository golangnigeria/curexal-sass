# ADR-0005: Decoupling Platform Bounded Context from Authentication

- **Status**: ACCEPTED / ENFORCED
- **Date**: 2026-07-27
- **Deciders**: Principal Systems Architect, Security Lead

## Context
Previously, platform bootstrap and owner creation logic was placed inside the Authentication module (`internal/modules/auth`). In an enterprise SaaS platform, authentication must only authenticate user credentials and issue sessions. It should not contain logic for initializing platform settings, marketplace configurations, or platform governance roles.

## Decision
We completely decoupled **Platform Management** into its own bounded context (`internal/modules/platform`).
1. `internal/modules/platform` handles initialization, settings, 7 governance roles, marketplace module settings, and platform dashboard telemetry.
2. `internal/modules/auth` focuses solely on verifying credentials, password resets, session rotation, and email verification.
3. Platform Bootstrap executes exclusively via CLI (`cmd/bootstrap` / `task bootstrap`). No REST bootstrap endpoint is exposed.

## Consequences
- Clean Domain Driven Design (DDD) boundaries.
- Authentication remains lightweight and fast.
- Platform administration operates in global scope without requiring tenant context headers.
