# ADR-0001: Schema-per-Tenant Multi-tenancy Architecture

- **Status**: ACCEPTED / ENFORCED
- **Date**: 2026-07-27
- **Deciders**: Principal Systems Architect, Lead Database Engineer

## Context
Enterprise healthcare organizations (hospitals, diagnostic laboratory networks, radiology centers) require strict data isolation due to HIPAA, ISO 27001, and national healthcare data privacy mandates. Shared-table multi-tenancy (`tenant_id` column in every table) carries a high risk of accidental data leaks during complex SQL join queries.

## Decision
We enforce **Schema-per-Tenant Multi-tenancy** in PostgreSQL for all clinical, diagnostic, and financial data. Every customer organization receives a dedicated PostgreSQL schema (`tenant_<slug>`).

## Consequences
- **Security**: Cross-tenant data leaks are physically impossible at the database level.
- **Operations**: Schemas are provisioned dynamically via DDL migrations executed by `internal/modules/provisioning`.
- **Querying**: Middleware dynamically executes `SET LOCAL search_path TO "tenant_<slug>", "public";` prior to handler queries.
