# Curexal V2 Product Requirement Document (PRD): Identity Platform (EPIC-001)

This document establishes the official product and technical specification for the Identity Platform in Curexal V2.

---

## 1. Module Purpose & Core Principles

The Identity Platform manages universal single sign-on (SSO) identities across the Curexal ecosystem.

### Key Architectural Principles
- **Universal Identity**: User accounts reside in the global `public.users` table. A patient, clinician, or scientist maintains a single login identity across independent multi-tenant workspaces.
- **Decoupled Identity vs Profile**: Credential data (`public.users`) is decoupled from profile data (`public.user_profiles`).
- **Cookie-First Authentication Strategy**: Access tokens (`curexal_access_token`, 15m) and Refresh tokens (`curexal_refresh_token`, 7d) are delivered exclusively via HTTP-Only, Secure, SameSite=Lax cookies. JWT tokens are never returned in JSON response bodies.
- **Hashed Refresh Tokens**: Refresh tokens are stored strictly as SHA-256 hashes (`public.sessions.refresh_token_hash`). Plain-text tokens are never stored in the database.
- **ULID Primary Keys**: All primary keys use sortable 26-character ULID identifiers generated by `primitive.ULID()`.
- **Token Reuse Anomaly Detection**: Reusing a rotated refresh token triggers automatic revocation of all user sessions and dispatches a `security.session_reuse_detected` event.

## 2. Database Schema Specifications (`public` Schema)

### Migration SQL: `001_create_identity_tables.sql`

```sql
-- Global Universal Users Table (Authentication)
CREATE TABLE IF NOT EXISTS public.users (
    id VARCHAR(26) PRIMARY KEY,
    email VARCHAR(255) NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    status VARCHAR(50) NOT NULL DEFAULT 'Active', -- Active, Suspended, Archived
    is_email_verified BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_users_email_lower ON public.users (LOWER(email));

-- User Profiles Table (Decoupled Profile Details)
CREATE TABLE IF NOT EXISTS public.user_profiles (
    user_id VARCHAR(26) PRIMARY KEY REFERENCES public.users(id) ON DELETE CASCADE,
    first_name VARCHAR(100) NOT NULL,
    last_name VARCHAR(100) NOT NULL,
    phone VARCHAR(50),
    avatar_url TEXT,
    timezone VARCHAR(50) DEFAULT 'UTC',
    locale VARCHAR(10) DEFAULT 'en-US',
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- User Sessions Table (Hashed Tokens & Device Tracking)
CREATE TABLE IF NOT EXISTS public.sessions (
    id VARCHAR(26) PRIMARY KEY,
    user_id VARCHAR(26) NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
    refresh_token_hash VARCHAR(64) UNIQUE NOT NULL, -- SHA-256 Hash
    device_name VARCHAR(100),
    device_type VARCHAR(50),
    user_agent TEXT,
    client_ip VARCHAR(50),
    is_revoked BOOLEAN NOT NULL DEFAULT FALSE,
    revoked_reason VARCHAR(255),
    last_used_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at TIMESTAMPTZ NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_sessions_user_id ON public.sessions (user_id);
CREATE INDEX IF NOT EXISTS idx_sessions_refresh_hash ON public.sessions (refresh_token_hash);

-- Email Verification Tokens Table
CREATE TABLE IF NOT EXISTS public.email_verifications (
    id VARCHAR(26) PRIMARY KEY,
    user_id VARCHAR(26) NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
    token_hash VARCHAR(64) UNIQUE NOT NULL,
    expires_at TIMESTAMPTZ NOT NULL,
    used_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Password Reset Tokens Table
CREATE TABLE IF NOT EXISTS public.password_resets (
    id VARCHAR(26) PRIMARY KEY,
    user_id VARCHAR(26) NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
    token_hash VARCHAR(64) UNIQUE NOT NULL,
    expires_at TIMESTAMPTZ NOT NULL,
    used_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Intrusion Detection & Login Attempts Table
CREATE TABLE IF NOT EXISTS public.login_attempts (
    id VARCHAR(26) PRIMARY KEY,
    email VARCHAR(255) NOT NULL,
    client_ip VARCHAR(50) NOT NULL,
    is_success BOOLEAN NOT NULL,
    attempted_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_login_attempts_email_ip ON public.login_attempts (LOWER(email), client_ip);
```

- `POST /api/v1/auth/register` (201 Created)
- `POST /api/v1/auth/login` (200 OK + HTTP-Only Cookie)
- `POST /api/v1/auth/logout` (200 OK)
- `POST /api/v1/auth/refresh` (200 OK + Token Rotation)
- `POST /api/v1/auth/verify-email` (200 OK)
- `POST /api/v1/auth/password-reset/request` (200 OK)
- `POST /api/v1/auth/password-reset/confirm` (200 OK)
- `GET /api/v1/auth/me` (200 OK)
- `GET /api/v1/auth/sessions` (200 OK)
- `DELETE /api/v1/auth/sessions/{id}` (200 OK)

## 5. Domain Events & Audit Log Catalog

### Published NATS Events
- `user.registered`: User account established.
- `user.logged_in`: Authentication session created.
- `user.logged_out`: Session explicitly revoked.
- `user.password_changed`: Password updated.
- `user.email_verified`: Account email verified.
- `user.session_revoked`: Specific session terminated.
- `user.refresh_rotated`: Refresh token safely rotated.
- `security.session_reuse_detected`: Token reuse anomaly detected; all sessions revoked.
